# Database

solis uses a single Supabase (PostgreSQL) table.

---

## Schema

Run the following in the **Supabase SQL Editor** after creating your project:

```sql
create table solis (
  id          bigint generated by default as identity primary key,
  title       text        not null,
  content     text        not null,
  image_url   text,
  tag         text        default 'Discussion',
  upvotes     integer     default 0,
  comments    jsonb       default '[]',
  created_at  timestamptz default now()
);

-- Enable Row Level Security (RLS)
alter table solis enable row level security;

-- NOTE: These open policies are intentional for this anonymous demo.
-- In a production app with auth, replace `true` with `auth.uid() = creator_id`.
create policy "Public read"   on solis for select using (true);
create policy "Public insert" on solis for insert with check (true);
create policy "Public update" on solis for update using (true);
create policy "Public delete" on solis for delete using (true);
```

---

## Column Reference

| Column | Type | Notes |
| ------ | ---- | ----- |
| `id` | `bigint` | Auto-incrementing primary key |
| `title` | `text` | Post title — required |
| `content` | `text` | Post body — required |
| `image_url` | `text` | Optional Cloudinary URL |
| `tag` | `text` | Category label, defaults to `'Discussion'` |
| `upvotes` | `integer` | Aggregate upvote count, defaults to `0` |
| `comments` | `jsonb` | Array of comment objects stored as JSONB |
| `created_at` | `timestamptz` | Auto-set to `now()` on insert |

---

## Access Pattern

All database access goes through the typed Supabase JS client in `src/lib/supabase.ts`. Post CRUD operations are encapsulated in `PostsContext` — no component talks to Supabase directly.
